Auth flow related APIs docs are below.  
Auth flow explanation:  
Users can sign up using the Sign-Up API. After users sign up, they receive an email with an OTP. Users must verify their accounts with this OTP before they can use them. See [Sign-Up API doc](/docs#tag/auth/POST/auth/signup), [OTP docs](/docs#tag/otp), and [verify account API doc](/docs#tag/account/POST/account/verify) for more details on how to sign up a user, verify OTPs and verify accounts.
Users can sign in to their accounts using the Sign-In API. If users haven't enabled 2FA on their accounts, after sending the correct data, they will be signed in and receive an access token and a refresh token in the `Set-Cookie` header and their account data in the response `body`. If 2FA is enabled, an OTP will be sent to their email and the API returns the username in the response. Then users must approve the OTP. After the OTP is approved, they can sign in with the given action key using the Sign-In 2FA API. After this, the returned response shape is the same as the response of the Sign-In API when 2FA is disabled. See [Sign-In API](/docs#tag/auth/POST/auth/signin) and [Sign-In 2FA API](/docs#tag/auth/POST/auth/signin/2fa) docs for more details.

- Refresh tokens are valid for 1 month, and access tokens are valid for 15 minutes. When an access token expires, you must refresh that access token to continue making authenticated requests. To do this, see [refresh API docs](/docs#tag/auth/POST/auth/refresh). The new access token and refresh token will be returned in the `Set-Cookie` header of the response.
