This API is used to refresh an access token. As explained in the [auth section](/docs#tag/auth), a refresh token is valid for 1 month and an access token is valid for 15 minutes. After an access token expires, to continue using authenticated endpoints, you must refresh that access token using the related refresh token. If a refresh token expires, the user must sign in again.

Notes:
- When users sign in, a session will be created for them. That session expires after 1 month, the same as the refresh token. To refresh an access token, its associated session must exist. If the session associated with the refresh token does not exist, the user must sign in again. A session can be deleted by the user or by an admin for security purposes.  
- If the refresh token in the associated session record does not match the sent refresh token, the sent refresh token, access token, and the session itself will be deleted for security purposes (tokens will be cleared via the `Set-Cookie` header). 
- When an access token is refreshed, the sent refresh token is rotated as well for security purposes. Because of this, ensure you send only one request with a refresh token at a time to this API. For example, if you send two requests with refresh token `A` at the same time, the first request rotates refresh token `A` to `B` and saves it in the session. Meanwhile, the second request still carries token `A`, detects that it does not match token `B` in the session, terminates the session, and clears both `access_token` and `refresh_token` in the response cookies, signing the user out.  
- When refreshing an access token using a refresh token, the new access token will expire in 15 minutes, but the expiration time of the new refresh token won't change. It will remain at the original expiration time.
